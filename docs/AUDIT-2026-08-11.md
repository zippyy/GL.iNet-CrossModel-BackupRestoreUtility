# OpenWRT branch audit

This audit was completed before changing the native package source.

## Branch relationship

- `OpenWRT` was audited at `db3f885` (`v1.1.0-17`).
- `main` was audited at `453ff5f`.
- The branches diverge after merge base `f2e6120`.
- `OpenWRT` contains the native LuCI package, shell backend, agentless SSH
  coordinator, validation backend, standalone IPK builder, and release workflow.
- `main` contains the older Node/Docker application plus a ten-commit GL.iNet
  Admin Panel companion-IPK series. The Node/Docker application is not part of
  the native package and is not being merged into `OpenWRT`.

## Relevant work on main

The relevant `main` work is the GL.iNet Admin Panel v4 integration under
`openwrt/glui-integration/`:

- an idempotent helper adds/removes a script tag in `/www/gl_home.html`;
- a browser hook adds a System menu item and a header shortcut to the LuCI app;
- an init script reapplies the integration after boot;
- install/remove hooks manage the integration lifecycle.

That behavior belongs in the primary architecture-independent IPK. A separate
controller/endpoint or GL-UI companion edition is unnecessary.

## Canonical-source violation

`scripts/build-openwrt-ipk.sh` copied the checked-in package and then ran
`scripts/patch-ipk-payload.py`. The patcher changed application behavior in the
package artifact without changing package source. It injected or changed:

1. creation of the LuCI Services parent route;
2. GL.iNet/LuCI-compatible string chmod modes (`0700` and `0600`);
3. reliable command exit-status capture around `io.popen()`;
4. correct multipart archive-only upload capture and a tar readability check;
5. deferred firewall and Wi-Fi reloads during remote restore;
6. validation-plan CSS, markup, request handling, and rendering in the view.

All of these behaviors must be checked in. The build may validate permissions,
syntax, package contents, and reproducibility, but must not rewrite runtime
code.

## Native implementation at audit time

### Backend

`glinet-crossmodel-backup` created only v1 `profile/` archives. It exported raw
UCI packages, a simple `opkg list-installed` text file, and optional custom file
archives. Restore used whole-package `uci import`, committed all UCI changes at
once, and had no strategy, device fingerprint, sanitization, checksum manifest,
rollback snapshot, semantic radio mapping, or portable adapter boundary.

### Remote coordinator

`glinet-crossmodel-remote` correctly streamed the backend so endpoints did not
need the IPK. It used classic SCP for Dropbear compatibility, transient password
files, `StrictHostKeyChecking=accept-new`, persistent known_hosts, transfer
verification, and cleanup traps. Limitations were password-only authentication,
MD5 transfer checks, and no router inventory or safe-apply confirmation flow.

### Validation

`glinet-crossmodel-validate` was read-only and reported `will_apply`, `warnings`,
and `skipped`. It handled basic model/architecture/radio/firewall/package checks,
but only understood v1 archives and did not enforce clone/device strategy
constraints, SHA-256 payload integrity, semantic capability mapping, or package
review classifications.

### LuCI

The main controller supported local and remote facts/create/restore plus a
controller-side profile list. Validation lived in a second controller and much
of its UI was build-injected. Profiles supported download only. There was no
saved router inventory, key authentication, inspect/rename/delete, retention,
strategy selector, or explicit validation gate before restore.

### Build and CI

The standalone builder produced the legacy gzip/tar IPK wrapper required by the
targeted GL.iNet OpenWrt 21.02 opkg and declared `Architecture: all`. GitHub
Actions built, checked the wrapper, published releases, and uploaded artifacts.
CI did not run unit/security fixtures or shell linting and validated behavior
that existed only after the payload patch.

## Clean-room boundary

`RemoteToHome-io/gl-portable-backup` was reviewed only through its public
documentation and file-level architecture. Its GPL-3.0-or-later implementation
source is not copied. The v2 schema, strategy rules, adapters, transport, tests,
and UI in this repository are independently implemented under this package's
existing MIT license.
